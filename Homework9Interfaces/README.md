# ДЗ 9. Интерфейсы и инверсия зависимостей

## Задача 1.1

1. В `List<IDamageable>` можно положить и игрока, и ловушку, потому что оба класса реализуют `IDamageable`. Для каждого объекта `ProcessDamage` вызовет `TakeDamage`. У игрока вызов уменьшит здоровье, а у ловушки выведет сообщение о поломке. В этом и состоит полиморфизм: вызов в цикле один и тот же, а поведение зависит от объекта.

2. По сигнатурам класс `Trap` выполняет требования интерфейса: у него есть свойство `HP` с чтением и записью и метод `TakeDamage`, который возвращает `bool`. Сам интерфейс в примере не говорит, что урон обязательно уменьшает `HP` или что должно означать значение `false`. Но если вызывающий код, как в случае с `Player`, воспринимает `false` как сигнал, что цель погибла, поведение ловушки будет странным. После сообщения о поломке чтение `HP` всё равно даст 10, а запись нового значения ничего не изменит. Если договориться, что после разрушения `HP` должно быть равно нулю, тогда ловушка нарушит этот договор.

3. `HealthPotion` реализует только `IHealable`, поэтому его нельзя добавить в `List<IDamageable>`. Компилятор сообщит, что `HealthPotion` нельзя неявно преобразовать в `IDamageable`. Кроме того, `ProcessDamage` вызывает `TakeDamage`, так что до `Heal` он вообще не доберётся. Чтобы вызвать `Heal` у зелья, будем работать с ним через `IHealable`, как в `ProcessHeal`.

4. Добавим реализацию `IsDead` в `Player` и `Trap`, потому что оба объявили, что реализуют `IDamageable`. У игрока свойство сможет проверять `HP <= 0`, а у ловушки будем хранить признак поломки и менять его при получении урона. Если свойство не добавить, компилятор сообщит для каждого из этих классов, что член интерфейса не реализован. `HealthPotion` менять не придётся: он реализует другой интерфейс.

### Дополнительный вопрос

```text
GameCharacter (абстрактный класс)
├── Player : GameCharacter, IInteractable, IHealable
├── Enemy  : GameCharacter
└── NPC    : GameCharacter, IInteractable
```

В `GameCharacter` вынесем здоровье и общий метод `TakeDamage`. Все три сущности получают урон одинаково, поэтому наследники смогут пользоваться одним методом и каждый будет хранить своё здоровье. Абстрактный класс подходит для общего состояния и кода родственных типов.

Через `IInteractable` объявим метод `Interact()` для диалога. Его реализуют `Player` и `NPC`. Через `IHealable` объявим `Heal(int amount)`, который реализует только `Player`. Интерфейсы подходят для отдельных возможностей: код диалога сможет работать с любым `IInteractable`, а код лечения будет принимать `IHealable`.
